# 微光竞技场 MVP 0.4：成长合约

## 运行

完整解压后双击 NeonArena.exe；与 NeonArena.pck 保持同目录，无需安装 Godot 或联网。

- WASD / 方向键移动，鼠标瞄准，按住左键射击。
- 累计击败 12 个目标；本局不足可以下局继续。
- 达标后，局内提示「结束对局后结算」，此时经验尚未到账。
- 撤离、阵亡和主动退出都会结束当前行动并结算。撤离仍可用：右下圆圈按住 E 约 1.2 秒，但这份合约不要求成功撤离。
- 暂停是暂停，不是结束；Esc / P 暂停与继续，窗口失焦自动暂停。
- 暂停界面的「退出游戏」或关闭窗口会正常保存并结束。强制结束或崩溃时，下次进入根据已保存记录补结算。
- 首通 80 + 120 = 200 经验，之后每次完成得 80。未达标不发完成奖励，但目标进度保留。
- 200 经验开放速射 / 机动改装；结算后回合约板可重新接取。

只处理当前一次接取；达标后的额外击败不预存成下一份合约。该细节为当前最小实现边界，后续可讨论。

## 存档与边界

progress.json 位于 exe 同目录；编辑器运行时位于源项目目录。有效目标计数发生时写入；奖励和已结算状态共同保存，避免恢复时重复领取。请在可写文件夹运行。

保存失败会显示提示。异常退出只恢复最后一次成功保存的状态，不承诺设备故障时尚未写入的数据可恢复。本地原型没有联网、服务器结算和防作弊。

新版使用带合约编号的存档格式，不自动导入0.1—0.3旧存档，避免将原案撤离型合约与成长型合约的首通/进度混用。旧版本和存档请保留在原目录。

## 源项目

Godot Standard 4.7.2 导入 project.godot，F5 运行。Main.gd 管理本地状态、战斗与界面；data/contract.json 保存本份合约参数；qa/ 为显式测试入口。

重新导出需安装匹配的 Godot Windows 模板，使用 Windows Desktop 预设。中文字体与许可证在 assets，运行包许可在 licenses。

## 复测

```powershell
.\NeonArena.exe --headless --quit-after 600 -- --qa-logic
.\NeonArena.exe --fixed-fps 60 --max-fps 60 --quit-after 1200 -- --qa-input
```

上述检查使用独立 QA 存档，不覆盖普通 progress.json。跨进程检查由开发端启动专用 QA 模式并强制结束自己启动的进程完成；不会结束用户正在玩的游戏。

## 本轮不做

本版只提供一份无需成功撤离的成长合约。需要撤离的合约仍可作为后续内容；还未提供合约选择池、刷新、多人助攻、完整采集、其他难度与更多奖励层级。


## 统一版对应

对外设计版本1.0，演示合约 CONTRACT_002「步枪成长训练」。原案例 CONTRACT_001「步枪火力校准」保留单局与本人撤离要求，只在设计案和网页规则模拟中展示。当前游戏只承载002；不宣称已实现可切换的多合约系统。奖励仍为每份合约首次80+120、之后80。合约名称、编号、目标与条件与统一包中的合约规则基准.json一致。
